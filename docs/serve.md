# Резидентный режим (`serve`)

`serve` оставляет процесс запущенным и выполняет команды по запросам. Запуск JVM и подготовка
контекстов JAXB происходят один раз, дальше команда стоит столько, сколько длится сама работа.

```
java -jar build/libs/md-sparrow-<версия>-all.jar serve
```

Процесс читает из stdin строки JSON, по объекту на строку, и отвечает в stdout тоже строками JSON.
Обе стороны в UTF-8. В stdout не попадает ничего, кроме ответов; диагностика идёт в stderr.

Первая строка после запуска сообщает о готовности, версии md-sparrow и версии протокола:

```json
{"ready":true,"version":"0.5.8","protocol":1}
```

## Запрос и ответ

```json
{"id":1,"args":["cf-md-object-get","Catalogs/Валюты.xml","-v","V2_20"],"cwd":"C:/проект/src/cf"}
```

`args` - аргументы, как у разового запуска. Кириллица и пробелы в них доходят как есть: аргументы
не проходят через командную строку JVM.

`cwd` можно не указывать. Относительные пути в аргументах и в файле параметров `read-json` и
`apply-mutation` считаются от него, а без него - от рабочего каталога процесса. Каталог должен быть
абсолютным и существовать.

```json
{"id":1,"exitCode":0,"stdout":"{\"kind\":\"catalog\",…}","stderr":""}
```

`exitCode`, `stdout` и `stderr` - то, что вернул бы разовый запуск с теми же аргументами в том же
каталоге.

Несколько правок одним запросом - пакет `apply-mutation` (`"op": "batch"`, см.
[write-session.md](write-session.md#пакет-операций)): операции идут одним сеансом записи и
публикуются вместе, пути в них считаются от `cwd` запроса, а `stdout` ответа - JSON-массив ответов
операций.

Запросы выполняются по одному в порядке поступления. Отказы и отмена ждущих запросов отвечаются
сразу, поэтому ответ с запросом сопоставляется по `id`.

## Отмена

```json
{"id":1,"cancel":true}
```

Ждущий запрос снимается сразу. Выполняемый прерывается между файлами в долгих чтениях: дерево и
граф метаданных, дерево подсистем, проверка выгрузки. Ответ на отменённый запрос:

```json
{"id":1,"exitCode":130,"stdout":"","stderr":"Запрос отменён."}
```

Запись не прерывается: если команда успела закончить, приходит её обычный ответ. Пакет
`apply-mutation` прерывается между операциями, до публикации: диск он тогда не меняет. Отмена
неизвестного или уже отвеченного запроса ничего не делает.

## Отказ

Строка, которая не разбирается как запрос, получает ответ с кодом 2, и сеанс продолжается:

```json
{"id":null,"exitCode":2,"stdout":"","stderr":"Строка не разобрана как объект JSON: …"}
```

В `id` возвращается значение из строки, если его удалось прочитать, иначе `null`. Отказ получают
также запрос с `id` другого запроса, на который ещё нет ответа, и запросы после завершения.

## Завершение

`{"shutdown":true}` или конец stdin: новые запросы больше не принимаются, принятые выполняются до
конца, процесс выходит с кодом 0.

Сбой команды сеанс не останавливает. После сбоя самой JVM, например нехватки памяти, процесс
отвечает на текущий запрос кодом 1 и выходит с кодом 1. В этом ответе стоит `"closing":true`:
следующих запросов процесс уже не выполнит.

## Что живёт между запросами

Контексты JAXB и метамодель 1С:EDT загружаются один раз на процесс. Файлы проекта каждый запрос
читает заново.
