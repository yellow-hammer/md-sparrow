# Эталоны узлов EDT: снятие с платформы и 1С:EDT

Новый реквизит, табличная часть, измерение, ресурс, команда, значение перечисления и признак
учёта в проекте 1С:EDT берутся готовыми из `src/main/resources/edt-golden/Nodes/<Класс>.xml`
(класс узла в метамодели EDT: `CatalogAttribute`, `TabularSectionAttribute`, `CatalogCommand`).
Собирать узел по схеме нельзя: у многих свойств значение по умолчанию в схеме EDT одно
(`fullTextSearch` = `DontUse`, `lineNumberLength` = 5), а платформа ставит другое (`Use`, 9), и
`group` у команды обязательна. Поэтому узлы записывает сама 1С:EDT из выгрузки, которую до этого
загрузила и выгрузила платформа.

## Как снято

1. `build_seed.py <голая выгрузка> <семя>` - к голым объектам каждого вида-владельца добавляет по
   узлу каждого вида. Узел минимальный: имя, синоним, пустой комментарий, тип (строка 10, у признаков
   учёта - булево), у команды - группа `FormCommandBarImportant`.
   Табличных частей две: пустая и с реквизитом. Идентификаторы - UUID v3 от имён, повтор даёт то же.
   Голая выгрузка - каталог с `Configuration.xml`, `Languages` и объектами-владельцами с
   `<ChildObjects/>`: справочник, документ, обработка, отчёт, планы видов характеристик, счетов и
   видов расчёта, план обмена, задача, бизнес-процесс, перечисление, журнал документов, критерий
   отбора, четыре вида регистров и последовательность. Её даёт `ibcmd` из минимального семени.
2. `platform.py <ibcmd> <семя> <каталог>` - платформа загружает семя (конфигурация с языком
   обычным `import`, объекты - `import files --no-check`) и выгружает его; каталог должен быть с
   коротким путём, иначе `ibcmd` на Windows падает. Платформа сама дописывает узлам свои значения
   по умолчанию.
3. `1cedtcli -data <ws> -command import --version 8.3.27 --configuration-files <каталог>/out
   --project <проект>` - 1С:EDT перекладывает выгрузку в свой формат.
4. `harvest.py <проект>/src <mdclass.ecore> <каталог эталонов>` - берёт из проекта по узлу на класс
   метамодели (класс - по схеме владельца из `schemas/edt/<версия>/ecore` namespace-forest) и
   пишет их с отступом верхнего уровня.

Снято 1С:EDT 2026.1.2.2 из выгрузки `ibcmd` 8.3.27.2214 (формат 2.20). Проверено, что те же узлы
(реквизит справочника и табличной части, команда, признаки учёта) 1С:EDT записала и при импорте
выгрузки, собранной Designer-путём md-sparrow, с точностью до идентификаторов и имён.

Эталоны одни на все версии платформы. Свойство узла, которого формат платформы проекта не знает
(`lineNumberLength` табличной части до формата 2.20), при добавлении узла убирается: 1С:EDT при
импорте выгрузки такого формата его не пишет, и в проекте остаётся умолчание схемы. Что знает формат,
видно по его модели (`FormatProjection.hasElement`), платформа проекта - по `Runtime-Version`. На Windows с
Java не той версии 1cedtcli может открыть окно IDE с диалогами: шаг 3 лучше выполнять там, где
1С:EDT уже настроена.
